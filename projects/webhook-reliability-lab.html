Webhook Reliability Lab

Signed event intake with deduplication, local queueing, retry backoff, and dead-letter handling.

Source code is included in the deliverable bundle. A public GitHub repository has not been created yet.

The problem

What this project addresses

Webhooks arrive more than once, sometimes late, and downstream services fail. Reliable integration requires authentication, idempotency, durable retries, and clear failure states rather than a one-shot POST handler.

Architecture

How the pieces fit together

Signed webhook→HMAC + timestamp→Idempotent queue→Retry / dead-letter

Boundaries are deliberately explicit to keep network access, application rules, and persistence separately testable.

Decisions & tradeoffs

What matters in the implementation

  • Inbound signatures use HMAC-SHA256 across the raw body and timestamp, checked with constant-time comparison.
  • Event IDs are deduplicated and accepted into a file-locked durable local queue.
  • Workers claim events, apply exponential backoff on failure, and dead-letter jobs after five attempts.
  • The worker is transport-independent in tests; a separate runner demonstrates HTTPS delivery to a configured destination.

Honest boundaries

What I would change for production

A single-host demonstration of at-least-once delivery, not a production message broker. Horizontal deployments need atomic database leases, lease fencing, monitoring, retries with jitter, and egress allowlisting. Downstream services must deduplicate X-Event-ID.
