SurfaceLint

Local-first public security posture checks, explainable results, and scan-to-scan drift.

Open GitHub repo ↗
The problem

What this project addresses

Security observations are often scattered across tools. A compact CLI can create a repeatable, inspectable baseline for common web and email controls without collecting data through a hosted service.

Architecture

How the pieces fit together

CLI→Concurrent checks→Finding model→History / drift / reports

Boundaries are deliberately explicit to keep network access, application rules, and persistence separately testable.

Decisions & tradeoffs

What matters in the implementation

  • Concurrent TLS, HTTP, and DNS checkers reduce total scan latency while findings remain sorted deterministically.
  • Each observation has a stable ID, status, severity, evidence, and remediation so reports explain what actually happened.
  • An explicit opt-in history store writes local JSONL snapshots; comparisons classify changed statuses by finding ID.
  • JSON-only stdout and an explicit failure threshold support predictable CI integration.

Honest boundaries

What I would change for production

v0.2 is a preview posture linter, not a vulnerability scanner. Failed DNS lookups can affect scores, and untrusted target submission would require DNS-pinning and private-network egress filters before deployment as a service. The next version can add security.txt, CAA, and cookie auditing.
